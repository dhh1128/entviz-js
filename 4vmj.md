# Port spec v16: fold the bech32 HRP into the fingerprint; move the segwit/Litecoin checksum to the suffix

- 2026-08-04T05:06Z Port spec v16 (see entviz docs/spec-change-log.md 'What's new in v16', committed 26de342 on 2026-08-04). Four parts: (a) fold the bech32 HRP into the fingerprint — hash '<hrp>1' || core — on every bech32 path: the generic <hrp>1<data> form, Bitcoin segwit bc1/tb1, Litecoin ltc1, Cardano Shelley addr1/stake1/addr_test1. Mechanism is prefix-fold, not in-core, because bech32's charset excludes b, i, o and 1. (b) Move the 6-char checksum out of the core and into the suffix for segwit and Litecoin, which alone kept it in the core; this MUST land with (a), because on its own it would create a bc1/tb1 collision. (c) Leave CashAddr unfolded and keep its 8-char checksum in the core — a deliberate exception, because its prefix is optional. (d) Fix the label rule: drop the trailing PREFIX slot only when the prefix minus a trailing ':' equals the PRIMARY string, otherwise show it — the v15 rule would delete a bech32 HRP from the label entirely. Then reproduce Tier A and Tier B against the regenerated corpus, which gains six vectors (osmo, btc-segwit-testnet, cardano-shelley, cardano-shelley-testnet, nostr-npub, nostr-nsec) and changes four golden rasters (btc-segwit, btc-segwit-p2wsh, cosmos, litecoin). WHY: before v16 a nostr npub1<payload> and the nsec1<same payload> secret key rendered byte-identically in every channel a human compares.
